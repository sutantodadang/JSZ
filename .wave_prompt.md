# Wave 50a: RegExp + Destructuring + staging/sm + Language/Expressions

You are working on JSZ, a JavaScript runtime/compiler written in Zig. This is a conformance push to reach V8 parity on test262.

## Target Areas

Focus on these non-overlapping areas (compiler, parser, regexp, bc_vm):

1. **RegExp spec compliance**: Fix regexp.zig edge cases — lookbehind, property escapes (\p{}), /u flag code-point semantics, non-ASCII ranges
2. **Destructuring edge cases**: Parser/compiler destructuring fixes — nested patterns, default values with complex expressions, rest in array/object patterns
3. **staging/sm**: SpiderMonkey staging tests in test262 corpus — fix failing staging tests
4. **language/expressions**: Conformance for language/expressions test262 category — binary/unary operators, assignment expressions, update expressions, comma operator
5. **Compiler/parser improvements**: General compiler and parser fixes discovered while fixing failures

## Process

1. Run `zig build` first to make sure baseline builds
2. Work through failures iteratively:
   - Run `zig build conformance-delta` or `zig build conformance-summary` to find failures
   - Fix one category/issue at a time
   - Run `zig build test` to verify unit tests still pass
   - Run `zig build differential` to verify differential tests still pass
3. After fixes, verify:
   ```bash
   zig build test && zig build differential && zig build conformance-delta
   ```
4. Commit and push:
   ```bash
   git add -A && git commit -m "Wave 50a: <description of changes>"
   git push -u origin feat/conformance-wave50a
   gh pr create --title "Wave 50a: <summary>" --body "Conformance push Wave 50a"
   gh pr merge --squash --delete-branch
   ```

## Important Rules

- NEVER delete the JSZ cron job
- If you hit API limits, just stop — next cycle continues
- Run `zig build test` frequently to catch regressions early
- Focus only on the areas listed above — other areas are being worked on in parallel
- Don't modify files outside compiler/, parser/, regexp/, bc_vm/ unless required by a fix
- Keep commits focused and described clearly
